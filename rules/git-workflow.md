# Git Workflow & Safety Protocol (True Git)

> Стандарты работы с Git и GitHub для Unity-проектов.  
> Исключает потерю данных, повреждение мета-файлов (`.meta`), конфликты слияния и сломанную историю.

---

## 1. Структура веток (Branching Strategy)

- **`main`** — стабильная ветка проекта. Код здесь обязан компилироваться и проходить тесты. Прямые коммиты в `main` без проверки сборки запрещены.
- **`feature/<name>`** — разработка новой фичи или механики (`feature/player-dash`, `feature/turret-shooting`).
- **`fix/<name>`** — исправление конкретного бага (`fix/navmesh-obstacle-carve`, `fix/null-ref-spawner`).
- **`chore/<name>`** — обновление пакетов, рефакторинг, документация, настройки проекта (`chore/update-packages`).
- **`backup/<name>`** — страховочные слепки перед масштабным рефакторингом, миграцией версий Unity или очисткой LFS (`backup/pre-unity-upgrade`).

---

## 2. Железные законы Unity в Git

1. **Файл и его `.meta` — единое целое**:
   * Любой файл или папка в `Assets/` имеет парный файл `.meta` с уникальным GUID.
   * **Запрещено** коммитить `.cs`, `.prefab` или `.asset` без соответствующего `.meta` файла (и наоборот).
   * Удаление или переименование файла обязано сопровождаться удалением или переименованием его `.meta`.
2. **Никакого мусора в репозитории**:
   * В `.gitignore` обязательно должны быть исключены: `Library/`, `Temp/`, `Logs/`, `UserSettings/`, `MemoryCaptures/`, `Recordings/`, `Build/`, `.vs/`, `.idea/`.
3. **Git LFS для тяжелых ассетов**:
   * Текстуры (`.png`, `.tga`, `.psd`), 3D-модели (`.fbx`, `.obj`), аудио (`.wav`, `.mp3`) и видео (`.mp4`) должны отслеживаться через Git LFS (`git lfs track "*.fbx"`).
4. **Запрет `push --force` в `main`**:
   * Ни при каких обстоятельствах не перезаписывать историю общей ветки.

---

## 3. Стандарт сообщений коммитов (Conventional Commits)

Все сообщения коммитов пишутся **на английском языке**, кратко и в повелительном наклонении:

`type(scope): imperative description`

### Типы (Types):
- **`feat`**: новая игровая механика, компонент или система (`feat(combat): implement toothpick thrust spherecast`)
- **`fix`**: исправление бага или ошибки компиляции (`fix(camera): correct trauma shake decay formula`)
- **`refactor`**: изменение структуры кода без изменения игрового поведения (`refactor(enemy): decouple steering from brain`)
- **`perf`**: оптимизация памяти, пулинга или вызовов (`perf(pool): preallocate shatter shard rigidbodies`)
- **`chore`**: правка конфигов, пакетов `manifest.json`, метаданных или правил агента (`chore(agents): add git workflow rule`)
- **`docs`**: обновление README, GDD или документации архитектуры (`docs(gdd): add arena dimension specs`)

### Принципы коммитов:
- **Атомарность**: один коммит — одно логическое изменение. Не смешивать рефакторинг с добавлением трех новых фич.
- **Рабочее состояние**: проект на каждом коммите должен успешно компилироваться (`unity recompile`).

---

## 4. Чек-лист перед слиянием (Pre-Merge Checklist)

Перед слиянием feature-ветки или пушем в `main`:
1. `unity recompile --project-path .` — компиляция завершилась без ошибок.
2. `git status` — нет потерянных или не отслеживаемых `.meta` файлов.
3. `unity command console --level error` — в консоли редактора нет критических ошибок и исключений.
4. Открытые PR проверены, конфликты решены локально.
