# Поиск первопричин и защита от оверинжиниринга

> Защита от зацикливания, накопления костылей и архитектурного усложнения в Unity.  
> Агент обязан устранять корень проблемы и писать минимально достаточный код без спекулятивной гибкости.

---

## 1. Лестница простоты Ponytail (Бритва Оккама)

Перед написанием любой строки кода агент мысленно проверяет ступени снизу вверх:

```text
7. Минимальный рабочий код (только если ступени ниже не подошли)
6. Можно ли решить в одну строку?
5. Уже установленный пакет решает задачу? (UniTask, DOTween, PrimeTween)
4. Встроенный функционал Unity покрывает фичу? (Physics, NavMesh, URP, Input System)
3. Стандартная библиотека C# (.NET) уже умеет это? (Mathf, Span<T>, Collections)
2. Это уже написано в проекте? (Сначала поищи grep'ом хелперы и утилиты рядом)
1. Нужно ли этому вообще существовать? (YAGNI — если фича спекулятивна, отбрось)
```

### Запреты на оверинжиниринг:
- **Никаких пустых абстракций**: интерфейс с одной реализацией, фабрика для одного объекта, сервис-локатор ради двух классов — запрещены.
- **Никакого кода «на будущее»**: если функционал не требуется прямо сейчас под текущую задачу — не создавай под него пустые классы и заделы.
- **Удаление лучше добавления**: кратчайший работающий диф всегда выигрывает. Самый надежный код — тот, который не пришлось писать.

## 2. Исправление первопричины, а не симптомов (No Crutches Policy)

Багрепорт или строка в консоли Unity всегда называют **симптом**, а не причину. Агент обязан найти исток проблемы, а не городить подпорки.

### Запрещенные костыли:
1. **Слепые `if (x != null)` по десятку мест**:
   * *Костыль*: объект удалился или не успел создаться, и агент добавляет проверки на null во все вызывающие методы.
   * *Первопричина*: нарушение жизненного цикла или утечка подписки на события. Чинить нужно место отписки или фабрику спавна.
2. **Оборачивание в пустые `try { ... } catch { }`**:
   * *Костыль*: заглушить `NullReferenceException` или `IndexOutOfRangeException`, спрятав ошибку под ковер.
   * *Первопричина*: невалидное состояние данных или пустая коллекция. Исправлять инвариант в модели данных.
3. **Хак с кадровыми задержками (`WaitForEndOfFrame` / `Delay(100)`)**:
   * *Костыль*: ждать 1 кадр в надежде, что чужой компонент успеет запуститься в `Start()`.
   * *Первопричина*: неверный порядок инициализации. Чинить через явный порядок вызова (Bootstrap / явный метод `Initialize()`).
4. **Флаги-костыли**:
   * *Костыль*: заводить переменные вроде `bool _isPatchApplied`, `bool _preventDoubleCall`, `bool _workaroundDone`.
   * *Первопричина*: размытая логика вызова. Сделать метод идемпотентным либо разделить ответственности.

### Порядок действий при починке бага:
1. **Проследи весь стек вызовов** до точки, где данные впервые стали невалидными.
2. **Найди всех потребителей через `grep`**: посмотри, кто еще вызывает этот метод или поле.
3. **Исправь проблему в одном общем источнике**: одна проверка или исправление контракта в точке зарождения данных чинит всех потребителей сразу и сохраняет проект чистым.

## 3. Правило 3 попыток (Anti-Loop Rule)

Если агент встречает ошибку компиляции C# или баг Unity:

1. **Попытка 1**: Внимательно прочитать полный текст ошибки и номер строки. Устранить первопричину.
2. **Попытка 2**: Если ошибка повторяется — проверить зависимости `asmdef`, `using`, версию пакетов в `manifest.json`.
3. **Попытка 3**: Если ошибка не уходит — **остановиться**. Запрещено вслепую делать 4-ю и 5-ю попытку.
   * Агент обязан остановиться, привести точные логи из консоли (`unity command console --level error`) и предложить альтернативные варианты решения через `ask_user_question`.

---

## 4. Защита чужого кода

- Не удаляй и не переписывай рабочий код проекта, если этого не требует поставленная задача.
- Не пытайся «причесывать» чужие модули по пути — это создает регрессии и засоряет историю коммитов.
- Не меняй `ProjectSettings/*.asset` без явной необходимости и предварительного согласования.
